### 実測結果3: 静的フィットの状態は「dayラベル」になっている

Ver.5 §5.4 Step (1) 相当の静的GLM-HMM（K=3・3次元入力・day単位の系列、`prior_sigma=2.0`、seeds=[0,1,2]、best log_prob −1004.26）を学習して確認した。

- $P(z)\ge0.8$ の残存率は全体84.4%（p_max平均0.927）だが、**day9は12.5%**。
- **day内で状態×試行タイプを釣り合わせた後に使える試行は14 dayすべてで0**。
- 閾値をかけない全試行で見ても、**1状態が90%以上を占めるdayが11/14**（うち11日は占有率ちょうど1.000）。**day内の状態切り替えは全期間で合計3回**（day6・day12・day14に各1回）、状態のrun長は中央値134〜156試行＝ほぼ1日まるごと。

つまりこのモデルが見つけている「内的状態」はセッション内の戦略切り替えではなく**日ごとの反応率の違い**で、状態変数がday識別子として使われている。6.4節のday内バランシングが空になるのはその直接の帰結。唯一の例外がday6で、状態の切り替わりが日内の崩壊と一致しており、十分大きい日内変化ならモデルが検出できることの裏付けにもなっている。

静的モデルにはdayごとの違いを表現する手段が状態変数しか無いので、状態がそこに吸われるのは構造的に自然。Dynamic GLM-HMMはday別GLM重みという専用の受け皿を持つため、day差が重みに吸収された結果として状態が日内の切り替えを担うようになる可能性はあり、その意味でこの結果は「Dynamic化が必要な理由」の実測的な裏付けでもある。

## 報酬閾値の変動が原論文に明記されていることを確認し、関連docを更新

ユーザーから「レバーの閾値が変動するってのは元論文に書いてるから探して」と指示され、`reference/sources/kondo2025_braidynbc_dataset_fulltext.pdf` のMethods "Tone-triggered lever-pull task" に該当記述を確認した。

> The required lever-pull time, Tpull, was adjusted according to the behavioral performance. The initial Tpull in the first session was set to 1ms. It was extended by 50ms when there was an 80% success rate in the previous 20 trials, up to the maximum duration of 400ms. We set a refractory period of 20 trials for these extensions... the initial Tpull in the next session was set to Tpull_final of the previous session minus 100ms. Tpull was never shortened within the same session.

同じ段落で、**キュー期間中に引けるのは1回だけ**であること（`T_pull` 経過前にnon-pulled状態へ戻ると、1秒の経過を待たずその時点でfailure確定・試行中断）と、**ITI中にレバーを引くとITIがさらに3–4秒延長される**ことも明記されていた。前者はSecond Pullが事実上発生しない理由（2026-09-01の監査で実測確認済み）を課題設計の側から説明する。後者は `docs/design_iti_poisson_emission.md` の有効露出 $\tilde\Delta$ の扱いに関係する（ITI長が押下に対して内生的）。

## 追加測定と、「成功率80%」の記述の訂正

ユーザーから「成功率は80%になってる？ Tpull だとどうなってる？」「Short Pullの時間はday間で伸びてる？」と問われ、ノート17に2.1節（staircaseと成功率の関係）と3.0節（Short Pullの保持時間のday変化）を追加して再実行した。

**訂正**: 上記「報酬閾値の変動が原論文に明記されている〜」の節で当初「staircaseが成功率をおよそ80%に保つ」と書いたが、これは誤りだった。論文の規則は**片方向のラチェット**（基準到達で上げるだけ、セッション内で下げない。下がるのはセッション間の−100msのみ）で、成功率を一定値に保つ制御ではない。実測でも `VG1GC-66` のday別成功率は中央値0.566（範囲0.280–0.883、全体0.548）で80%には程遠く、20試行移動窓の成功率が0.8以上だった割合は全day平均13.7%（day8・day9・day15は0%）。閾値の引き上げは全14日で計23回（day中央値1回）。`reference/kondo2025_braidynbc_dataset.md`・`docs/data.md`・`docs/requirements_ver5.md`・`CLAUDE.md`・`docs/RQ.md` の該当箇所を訂正した。「成功率は学習曲線として使えない」という結論自体は変わらない（理由が「80%に固定される」ではなく「上達が難度の上昇で相殺される」に変わる）。

**Tpull_final でも単調な学習傾向が無い**: 推移は .05 .15 .30 .40 .40 .40 .30 .20 .25 .20 .15 .10 .30 .20 で、day index相関は Spearman −0.125（p=.671）。day1–5で上限0.40に到達し、day5–7で維持、day8以降は後退する（day8・9・13・15は引き上げ0回）。後退は運動能力の低下ではなく「20試行移動窓で80%に達しなくなった」ことによるもので、従事の問題として読める。**Day 1–15 が単調な学習過程になっているという前提は、この個体については成り立たない。** 論文のクラスタA（早期到達・維持、n=7）／B（後期到達、n=18）のどちらにも素直には当てはまらないので、他個体との比較が要る。

**Short Pull の保持時間は day 間で伸びない**: 中央値の推移に単調傾向なし（Spearman +0.245、p=.420）。閾値に対する相対値（`pull_duration / T_pull`）でも +0.335（p=.263）で有意でなく、閾値そのものとの相関も +0.185（n.s.）。むしろこの比は13 day中11 dayで1を超える（中央値1.4〜3.8倍）——ギャップ埋め後の測定では「閾値の数倍握っているのに Short Pull」が常態、という接触途切れの構図がday別にも一貫している。例外は day6（比0.48、`too_short` 80%）で、日内崩壊の日だけは本当に引けていない。合算カテゴリの内訳自体もdayで安定せず、`dropout` 比は0.20〜0.77の範囲で振れる。

なお系統Bは現状すでに3類型を1カテゴリ（Short Pull）にまとめており、3類型をカテゴリに割る案は7節に「未定」として置いてあるだけ。今回の測定はまとめる側（現行仕様）を支持する。

## 要件への含意（未反映）

実測結果を踏まえた次の3点は設計判断を要するため、要件定義には反映していない（報酬閾値の件は上記のとおり反映済み。ただし「閾値をday共変量として持つか、閾値がほぼ一定の区間に限るか」の選択は未決定のまま記載している）。

1. **§6.4のバランシングに代替が要る**。候補は (a) day単位をやめてday群／全体でバランシング、(b) 日内で状態が振れるようKと入力を見直す、(c) day回帰を諦めて前半／後半の2群比較にする。あわせて $P(z)\ge0.8$ がday9をほぼ消す点の扱いを決める。§6.4・§6.7を確定させる前に、動的フィットで日内の状態切り替えが実際に生じるかを確認する必要がある。生じなければ状態＝dayなので「皮質から状態をデコード」は「皮質からどのdayかをデコード」と区別できず、RQ1が成立しない。
2. **系統Bは探索的位置づけへ格下げが妥当**（解釈の限定は反映済み）。§5.5に「系統Bを主系統に採る条件」を書くなら今回の数値が基準になる。
3. **日内の試行indexを扱う手当て**（入力に入れる／日内分割）の検討。

また §5.3 が併走を求めている $\alpha\to0$ ベースライン（＝今回のモデル）の状態は**解釈してはいけない**ことが確定した。

## ノート17に Dynamic GLM-HMM を実装

要件5.2〜5.4節の Dynamic GLM-HMM（Cuturela et al. 2024）をノート17の6節に実装した。`model_type ∈ {'standard', 'partial', 'dynamic'}` の3段階、スケーリング付き前向き後向き、重みのMステップ（全day同時のL-BFGS-B）、遷移行列の閉形式MAP、ブロック分割CVと欠測マスクでの評価を含む。

**公開実装との差**: 重みのMステップは、公開実装がセッション昇順のGauss–Seidel型なのに対し、全day・全状態を1回のL-BFGS-Bで同時最適化する。式1の連鎖事前分布から導かれる罰則付きECLLをそのまま最大化するので停留点は同じ。

### 合成データでの検証

14 day × 170試行、$K=2$、真の $\alpha=0.30$ のランダムウォークで生成したデータで、状態復元 0.937、重み軌跡の真値との相関 0.982（平均絶対誤差 0.222、真値の範囲 ±2.8）。5-fold CVは $\alpha=0.01$（ほぼ静的）を明確に棄却する。

### 実装の検証で判明した、初期状態分布 $\pi$ の影響

自前実装の `'standard'` が §4 の ssm 静的フィットと大きく違う状態構造（日内切り替え 108回 vs 3回）を出したため追跡した。

- **両実装は同一パラメータで完全に一致する**。ssmの学習済みパラメータを自前の前向き後向きに通すと data log-likelihood が両者とも −988.707（差 1.14e-13）。
- 差は最適化の到達点で、**ssmの解のほうが尤度が高い**（−988.71 vs 自前 −996.69）。ssmを20 seed回しても全seedが日固定型の解に収束し、log_prob と日内切り替え回数の相関は −0.465（尤度が高い解ほど切り替えが少ない）。**「静的フィットの状態はdayラベル」は局所解ではなく、この定式化での最良解**である。
- **原因は $\pi$ の扱い**。Cuturela et al. 2024 は $z_1^s \sim U(\{1,\dots,K\})$ と一様固定するが、`ssm`（Ashwood系譜）は $\pi$ を推定する。ssmの解を一様 $\pi$ で評価し直すと −995.529 で、**6.82 nats** 不利になる。日ごとに状態がほぼ固定される解では「その日がどの状態で始まるか」を $\pi$ が担うため、一様固定はその解を構造的に不利にする。dayが14本しかないので $\pi$ は無視できる細部ではない。

対処として、要件5.4節の手順どおり `'standard'` 段は ssm（20 seed）に任せ、その最良解を `'partial'` / `'dynamic'` の初期値にする構成にした。実装には `fit_pi` / `pi_init` を追加し、推定 $\pi$（既定）と一様 $\pi$（Cuturela式）の両方を報告する。

### 実データでのハイパーパラメータ選択（$K=3$、5-fold CV、held-out LL/試行）

| 段階 | test LL/試行 | SE |
| :--- | ---: | ---: |
| standard（全day共通） | −0.4203 | 0.0086 |
| partial $\alpha=0.01$ | −0.4202 | 0.0086 |
| partial $\alpha=0.1$ | −0.4161 | 0.0086 |
| partial $\alpha=1$ | −0.3957 | 0.0089 |
| partial $\alpha=10$ | −0.3849 | 0.0099 |
| **partial $\alpha=100$（グリッド端）** | **−0.3791** | 0.0096 |
| dynamic $\kappa=10^4/10^3/10^2$ | −0.3798 | 0.0093 |
| dynamic $\kappa=10$ | −0.3832 | 0.0104 |
| dynamic $\kappa=1$ | −0.3840 | 0.0095 |

- **day別の重みは効く**: standard → partial で +0.041 nats/試行（SEの4倍以上）。
- **「緩やかな変化」という前提は棄却される**: $\alpha$ は単調に改善してグリッド上端（100）で最良。$\alpha=100$ は事実上ランダムウォーク事前分布を外した状態で、day別に独立な重みと変わらない。$\alpha=0.01$ が standard とほぼ同値（−0.4202 vs −0.4203）で、$\alpha\to0$ の極限が正しく実装できていることの裏付けにもなる。
- **day別の遷移行列には利得が無い**: $\kappa \geq 100$ で頭打ちになり、partial（−0.3791）が dynamic の最良（−0.3798）をわずかに上回る。

状態数の選択（$\alpha=100$、$\kappa$ 最良値に固定、`'dynamic'` 段）:

| $K$ | 1 | 2 | 3 | 4 | 5 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| test LL/試行 | −0.4048 | −0.3926 | −0.3838 | −0.3776 | −0.3818 |
| SE | 0.0073 | 0.0085 | 0.0099 | 0.0113 | 0.0099 |

$K=1$ のみ明確に棄却され、$K=3,4,5$ は互いに1 SE以内。既定値 $K=3$ は最良（$K=4$）から 0.006（SEの約0.6倍）以内なので維持は妥当だが、このデータ量では $K$ を鋭く決められない。

### 8節Step 6の関門: 日内の状態切り替えは生じる

| 指標 | standard（ssm解） | dynamic（$\alpha=100$, $\kappa=1000$） |
| :--- | ---: | ---: |
| day内の状態切り替え（合計 / day中央値） | 8 / 0 | 28 / 2 |
| 1状態が90%以上を占めるday | 8/14 | 0/14 |
| 最頻状態占有率の中央値 | 0.981 | 0.613 |
| state run長の中央値 | 104試行 | 48試行 |
| $P(z)\geq0.8$ 残存率 | 0.844 | 0.723 |
| day内バランシング後の使用可能試行（全day計） | 0 | **372** |

**動的化によって状態はdayラベルから脱する**。全14 dayで複数状態が混在するようになり（例 day1 は 0.697/0.118/0.184）、day内バランシング後の使用可能試行が0から372試行（8 dayで>0、6 dayで0）に増える。これは §5.3 で立てた仮説——静的モデルにはday差を表現する手段が状態変数しか無いので状態がそこに吸われる、動的モデルはday別重みという受け皿を持つので状態が解放される——を実測で支持する。held-out尤度でも partial > standard なので、単なる過適合ではない。

$\pi$ の扱いに対する感度: 一様 $\pi$ に固定しても日内切り替え回数は 28回で変わらない（data log-likelihood は partial で −890.27 → −910.52 と20 nats悪化するが、状態構造の結論は変わらない）。

ただし6節（皮質デコード）に進むには、まだ2点が残る。day別の使用可能試行は中央値30程度と薄く、6/14 dayは依然0。そして選ばれた $\alpha$ がグリッド端であることは、Ver.5の「日をまたぐ緩やかな変化」という設計思想そのものがこのデータでは支持されないことを意味する。

## ノート17のDynamic GLM-HMMの状態退化を診断し、著者実装で回し直した（ノート18）

### 診断

ノート17の動的フィットが返す解をキャッシュから開いて調べたところ、**状態が「セッション内の時計」になっていた**。

- 共有遷移行列の対角が `[0.989, 1.000, 0.966]` で、state 1 の行が `[0, 1, 0]`（吸収状態）。
- 14 day すべてが例外なく `2 → 0 → 1` の同じ順序の3セグメントに切られる。「day内28回の切り替え」が 14 × 2 で揃っていたのはこのため。
- 状態別の day 内正規化位置は state 2 が 0.101 ± 0.080、state 0 が 0.439、state 1 が 0.751。
- state 2 の試行index中央値は14、81%が $k<30$。History の指数フィルタを day 頭で0から始めているため、$k=0$ の `x_hist_z` が $-2.49$、`x_rew_z` が $-2.01$ という決定論的な過渡が全 day で反復されており、そこに state 2 が張り付いていた。
- $\alpha=100$ では鎖項の係数が $10^{-4}$ になり day 1以降の重みが無拘束。$\max|W| = 54.7$、42個の (day, state) セルのうち9個が20試行未満、2個は完全分離（day4/state1 は14試行すべて $y=0$、day9/state1 は3試行すべて $y=0$）。
- `ssm` の `StationaryTransitions` は `log_prior()` が0の素のMLEで、自前実装が足していた sticky Dirichlet（対角10）とは目的関数が違う。`ssm` の解から `'standard'` を再学習すると data LL が −988.71 → −989.61 と悪化して止まるのはこのため（最適化の失敗ではない）。

公開実装 `lenca56/dynamic_glmhmm` のコードを確認すると、重みへの絶対的なL2は `model_type == 'standard'` にしか入らず、`'partial'`/`'dynamic'` は差分項だけ・セッション0はアンカー無し。**この点は論文のモデルそのもの**で、自前実装の欠陥ではなかった。一方で本番スクリプトの $\sigma$ グリッドは $10^{-3}$–$10^{3}$、選択値は $10^{0.5}=3.162$ と内点である。

### ノート18

`external/dynamic_glmhmm`（`.gitignore` 済み）に公開実装をクローンし、$K=3$・系統A固定で回し直した。$K$ と $\kappa$ の掃引はしていない。

修正は2つ。(1) History の指数フィルタを全dayプールの定常値（$h_0=2.166$, $r_0=2.706$）から始める。(2) $\sigma$ を論文と同じ $10^{-3}$–$10^{3}$ グリッドでCVし、列別 $\sigma$（Bias vs History 2列）も試す。

**$\sigma$ のCVは修正前後の両方の入力に対して回した**。系列・観測・fold分割は共通で入力の day 冒頭だけが違うので、切り分けになる。

結果:

- $\sigma$ は**両方の入力で内点（$\sigma=1$）**が最良。**グリッド端への張り付きは History の過渡ではなく、自前実装に由来していた**。前回ユーザーに説明した「$\alpha$ は上から識別できない定式化になっている」は、公開実装では成り立たない。
- 遷移行列は全成分正、day別の切り替え回数は 0–6 回とばらつき、状態別の day 内位置は 0.49–0.66（sd 0.28–0.32）。$\max|W| = 2.7$。時計への退化は解消した。
- History の初期値を直すと、1状態が90%以上を占める day が 11/14 → 6/14。
- 列別 $\sigma$ は Bias 座標の掃引幅が 0.0058 で fold間SE 0.0058 と同じ。利得なしと判断し、History 座標の掃引は打ち切った（大きい $\sigma$ は L-BFGS の反復が急増し、$\sigma=10^2$ の1点で約48分）。
- $P(z)\geq0.8$ の残存率は 0.351 に下がり、**day内バランシング後に使える試行は全day計36件（day12のみ）、13/14 dayで0件**。ノート17の372件は退化した状態から出た数字だった。
- day別の重みを持つ利得は standard 比 +0.0057 nats/試行（paired SE 0.0032、$t=1.80$）。

### 実行方法についてのメモ

バックグラウンド実行がこの環境で繰り返し kill されるため、フィットは前景で時間予算付きに分割して回した（`--budget` 秒を超えたら次のユニットに入らず終了し、完了ユニットは都度 `data/cache/ver5_note18.pkl` に保存して再開できる）。全計算は約2時間。ノート本体はキャッシュを読むだけなら数十秒で通る。
