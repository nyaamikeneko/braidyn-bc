## Ashwood et al. 2022 の多段階フィッティング手順を調査（コミット add7ca4）

`reference/ashwood2022_discrete_strategies.md` の「モデルの定義」節に、Methods 4.1.5 の3段階フィット手順（全動物連結GLM → global fit → 個体別fit）と、事前分布のグリッドサーチ範囲・選択値（IBLで $\alpha=2$・$\sigma^2=2$）を追記。

公開コード [zashwood/glm-hmm](https://github.com/zashwood/glm-hmm) を確認したところ、**global fit と個体別fit で事前分布の扱いが違う**ことが分かった。global fit は `transition_alpha=1`・`prior_sigma=100` でほぼ無情報にしており（コード中のコメントも `# perform mle => set transition_alpha to 1`）、実質MLEに近い挙動。個体別fitはグリッドサーチで選んだ値をそのまま使う通常のMAP推定。この違いは論文本文には書かれておらず、コードでしか確認できない（2026-09-01 GitHub `main` で確認）。本リポジトリでVer.5のglobal pooled fit（`requirements_ver5.md` 5.4節「初期値」）を実装する際に効いてくる。

## Ver.5要件定義のレビュー（Hulseyとの整合性確認）と3点の修正（コミット 179ad66）

ユーザーから「今の要件定義で問題あるとこある？マルチタイプ予測はhulseyと同様になってる？」と問われ、`reference/hulsey2024_arousal_movement.md` の原文引用（41-46行）と `requirements_ver5.md` §5.1系統Bの式を直接突き合わせた。

- **Hulseyとの相違点（本題）**: Hulsey et al. 2024の多項GLM-HMMは全カテゴリ（L/R/No response）が独自の重みを持つ**対称パラメータ化**で、識別性は重みへの平均0・分散2のガウス事前分布（MAP推定）に委ねている。特定カテゴリを0に固定してはいない。一方、本Ver §5.1系統Bは **No Reactionの重みを0に固定する参照カテゴリ型**で、Hulseyとは識別性の扱いが異なる。数学的にどちらも表現力はほぼ同等だが、「Hulsey et al. 2024の3値拡張を4値へ拡張する」という従来の書き方は、この設計判断がHulsey由来でないことを隠していた。参照カテゴリ固定を選ぶ理由（$C=2$に落とすと系統Aと厳密に一致し、実装検証テストに使える）を明記し、Hulseyのコード（`ssm`改変版）をそのまま流用できる前提を否定する注記を§5.1に追加した。
- **他に見つけた2点**:
  1. **§8冒頭の説明文とステップ番号のずれ**: 「Step 4–6を系統ごと、Step 7で比較」と書かれていたが、実際の番号付きリストではStep 7=Cortex Decoding、Step 8=系統の比較で、前回の編集（Cortex DecodingをStep 8→7に繰り上げ）で説明文を直し忘れていた。「Step 4–7を系統ごと、Step 8で比較」に修正。
  2. **Second Pull吸収時のWindow境界が未定義だった**（§2.1）: 属する音提示試行のラベルに吸収するとだけ書いてあり、`t_end`をSecond Pullの終了時刻まで延長するかが不明だった。延長しない（元の音提示試行の`t_start`〜`t_end`のまま、6.2節の皮質特徴量の基準onsetも元の`pull_onset`）と明記し、Second Pullの延長分の情報は本Verでは捨てる旨を追記した。
- ユーザー承認により3点とも `docs/requirements_ver5.md` に反映済み（§1・§2.1・§5.1・§8・変更履歴）。

## pull duration・試行窓・Short Pull閾値判定の監査

ユーザーから「レバー引き時間・試行の開始終了時間・Short Pullが閾値を超えてるかに問題はあるか、コードとデータから判断して」と問われ、`VG1GC-66` 全14日に加え `VG1GC-105` / `VG1GC-116` でも `src/glmhmm_ver4.py` を実行して確認した。

**問題なしと確認できたもの**: `t_end < t_start` 0件、`t_onset` が窓外 0件、試行窓どうしの重複 0件、`_action_end_time()` のセッション末尾までの暴走 0件、No Reaction に `t_onset` が付く事故 0/555件。NWBとCSVの `start_time` / `stop_time` / `pull_onset` / `pull_duration_for_success` は浮動小数点精度（1e-13）まで一致し、違いは miss/failure ラベルの入れ替えのみ（`pull_onset` の有無で判定する現行実装は正しい）。`reaction_time` == `pull_onset - start_time`（誤差±0.056秒＝1〜2フレーム）。

**見つかった問題**:

- **`pull_duration` が課題自身の測定値と系統的にずれる（重大）**: CSVの `first_diff` 列（公式試行2358/2359件に値あり）は、検証の結果 **生 `state_lever` の `pull_onset` からの連続保持時間**だった（`raw_hold - first_diff` の中央値 0.0334秒＝1/30秒、1803件中1800件が1フレーム以内で一致）。現行 `pull_duration`（ギャップ埋め後の `cleaned_lever` で測定）との差は公式試行1803件中1194件（66%）で0.05秒超、Success で中央値 +0.267秒・最大 +5.67秒、Short Pull で中央値 +0.433秒。**閾値超過率が反転する**: Short Pull のうち `pull_duration >= thr` は VG1GC-66 で 326/511（63.8%）だが、`first_diff >= thr` では 14/511（2.7%）。VG1GC-105 は 42.7% vs 8.5%、VG1GC-116 は 49.2% vs 5.6%。原因は1回の "pull" が生信号では複数バウトになっていること（Success の65%、Short Pull の67%が2バウト以上、最大11バウト。極端な例は day13 の Success で生の連続保持0.133秒→`pull_duration` 5.40秒）。`CLAUDE.md` の「Short Pullのうち閾値を下回るのは36.1%だけ」はギャップ埋め後の値に基づく記述で、連続保持で測ると97%以上が閾値未達。
- **`pull_duration_for_success == 0` の試行がある**: VG1GC-66 で68件（day1/day3の整形期）、VG1GC-105 で106件、VG1GC-116 で141件。閾値0との比較は自明に真になるので閾値集計から除外が要る。
- **Success の `t_end` が実際の押下を含まない**: `pull_end > t_end` が VG1GC-66 で 176/1293（13.6%）、VG1GC-116 で 285/721（39.5%）。
- **`Second Pull` は事実上デッドコード**: VG1GC-66 で0件、VG1GC-105 で0件、VG1GC-116 で11152試行中1件。cue（`state_task==1`）が押下時点で終わる（cue長の中央値0.33〜0.97秒）ため、`onsets_in(t0, t1, task=1)` に2本目が入る余地がない。
- **報酬フェーズ中の押下501件が試行にならない**: `state_task==2` のonsetは `used` マークだけされて `x_hist` にも入らない（Success 1293件に対して501件）。
- **`t_onset` が公式 `pull_onset` から0.05秒超ずれる試行が8件**（最大0.87秒、day10のShort Pull）。`nearest_onset()` が許容0.05秒で失敗し `in_sound[0]` に無条件フォールバックした結果、別の押下を掴んでいる。

いずれも修正は未実施（判断の依頼だったため）。`GAP_FILL_LIMIT` を変えるか `first_diff` を正とするかは解析方針の判断。

## 試行系列の構造的問題の特定と、Ver.5の方針転換

上記の監査中に、`x_stim == 0` の試行（No Sound Pull）4386件が**全件 y=1** である（`P(y=1|x_stim=0) = 1.000` が推定値ではなく定義）という構造的問題を発見し、ユーザーの求めに応じて解決策を先行研究と突き合わせて提案した。

**実測で確認した3つの帰結**:

1. **完全分離は系統Aでも起きる**。無正則化ロジスティック回帰で `C` を緩めると $w_{bias}$ が $+1.07 \to +8.49$、$w_{stim}$ が $-3.14 \to -10.50$ と発散する一方、和は $-2.07 \to -2.02$ で不動。識別されているのは和（音提示試行の切片）だけで、Ver.4 の `prior_sigma=2.0` で得られる個別値は事前分布が決めている。**`requirements_ver5.md` 旧§5.4 の「系統Aでは起きない」は誤りだった**（潰れること自体が分離の原因）。
2. **`x_hist` が理論上限に飽和**。$\alpha_{act}=0.65$ の上限 2.857 に対し中央値が上限値そのもの、71%の試行が2.8超、82%が2.5超。day平均は ITI試行の割合と $r=+0.694$ で相関する一方、day index とは $r=+0.051$。学習ではなく自発押下の密度を測っている。
3. **滞在時間がdayをまたいで比較できない**。試行/分が 12.5〜26.2 と2.1倍ばらつく。

**先行研究の確認**: `reference/` 全文と追加調査の結果、GLM-HMM系譜（Ashwood 2022 / Cuturela 2024 / Hulsey 2024 / Mohammadi 2025 / Aloor 2026）で**行動が起きたこと自体で試行を定義する例は一つも無い**。試行系列は必ず課題側が外部から決めている。Hulsey は課題設計側でITI中の舐めがITIをリセットするようにして自発行動が試行にならないようにしている。Cazettes 2025 は例外的に自己開始のlickボウトを系列にするが、目的変数はボウトの属性（連続失敗数）であって「ボウトが起きたか」ではない。

**提示した方策**（A: ITIの時間ビン化 / B: 系列を音提示試行のみに / C: cue試行GLM-HMM＋状態依存Poisson過程 / D: 現構造の緩和策）のうち、**ユーザーの判断でBをVer.5のメイン、Cを今後の拡張とする**ことが決定した。

## 方策Cを別docに切り出し

`docs/design_iti_poisson_emission.md` を新規作成。Ver.5本体の要件ではない設計メモとして、状態依存Poisson emissionの定式化・EMの更新式・実装の粒度・検証計画を記載した。要点:

- 入力ではなくemissionにする理由（Ver.5が $\lambda_k \equiv \lambda$ の特殊ケースになり、held-out尤度の比較が「自発レートは状態に依存するか」の検定になる）。
- $\lambda$ のM-stepに閉形式解がある（事後確率重み付きの総押下数÷総露出時間）。動的化（$\eta_k^s = \log\lambda_k^s$ のランダムウォーク）では閉形式は失われるが狭義凹性は保たれ、$(w, \eta)$ 同時に凹なのでM-stepの大域最適が保証される。
- **Poisson仮定の実測検証**（`VG1GC-66` 全14日、cue試行2359件）: 直前ITI長は平均8.90秒・中央値4.97秒、自発押下数は平均1.85・ゼロが51.5%、保持による不感時間は9.3%。Pearson分散比はプール単一 $\lambda$ で1.42だが、day別 $\lambda$ にすると0.51〜1.96（多くは1前後、後半dayは過小分散）。**day別レートを許せばPoissonが素直**。
- **状態依存性の予備検査**: $n_t$ に2成分Poisson混合を当てると $\lambda_{low}=0.169$、$\lambda_{high}=0.519$（3.1倍）、$\Delta\mathrm{BIC}=+612$ で単一レートは強く棄却される。
- 方策A（ITIビン化）は本設計の離散近似であり、$W\to0$ でPoisson対数尤度に一致することを示した。$W$ 依存（$y=1$率が $W=0.5$秒で0.104、$5.0$秒で0.839）は離散化誤差そのもの。
